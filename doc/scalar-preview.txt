1. Introduction                                  *scalar-preview-introduction*
                                                              *scalar-preview*

scalar-preview.nvim starts a local preview server for an OpenAPI/Swagger
file via Scalar's `@scalar/cli`, and opens it in your browser. The preview
reloads automatically whenever you save the file.

This plugin shells out to `@scalar/cli` as an external process; it bundles
no Scalar source and is not affiliated with Scalar. See
|scalar-preview-license|.

==============================================================================
2. Requirements                                  *scalar-preview-requirements*

- Neovim >= 0.10 (uses |vim.ui.open()|)
- Node.js >= 24 and `npx` available on `$PATH` (required by `@scalar/cli`)

Run `:checkhealth scalar-preview` to verify both -- see
|scalar-preview-health|.

==============================================================================
3. Commands                                          *scalar-preview-commands*

                                                              *:ScalarPreview*
:ScalarPreview          Start (or restart, for a different file) the preview
                         server for the current buffer's file, and open it
                         in your browser.

                                                          *:ScalarPreviewStop*
:ScalarPreviewStop      Stop the preview server, if one is running.

                                                        *:ScalarPreviewToggle*
:ScalarPreviewToggle    Start the preview server if none is running for the
                         current buffer's file, otherwise stop it.

4. Configuration                                *scalar-preview-configuration*

                                                      *scalar-preview.setup()*
require("scalar-preview").setup({opts})

    Merges {opts} into the plugin's configuration. Calling it is optional;
    every field below has a default and setup() itself does not need to be
    called at all if the defaults suit you. A field with an invalid type
    (or, for |scalar-preview-cli_version|, an invalid shape) is rejected on
    its own, with a notification explaining why, and falls back to whatever
    the configuration already had for it -- the rest of a setup() call is
    unaffected.

    Fields of {opts}: ~

    port        (number, default: `8000`)
                The local port the preview server listens on.

                                                         *scalar-preview-host*
    host        (string, default: `"localhost"`)
                The hostname used to build the URL opened in your browser.
                This is NOT passed to the underlying CLI and does not
                control who can connect; use |scalar-preview-bind| for that.

                                                         *scalar-preview-bind*
    bind        (string or nil, default: `nil`)
                The IP address the preview server listens on. Unset, it
                listens on every network interface, so anyone on your
                network can reach it. Set it to `"127.0.0.1"` so only this
                machine can: >lua
                    require("scalar-preview").setup({ bind = "127.0.0.1" })
<
                Other values: `"::1"` (IPv6 loopback only), `"0.0.0.0"` (every
                IPv4 interface, e.g. in a container whose forwarded port must
                be bound to all interfaces), or one of your machine's own
                addresses. It must be an IP address; a hostname such as
                `"localhost"` is rejected. A rejected value is reported and
                ignored, so the server then listens on every interface, as
                if `bind` were unset.

                `@scalar/cli` has no option for this, so the plugin starts it
                with `NODE_OPTIONS=--import=<scripts/bind-loopback.mjs>`,
                keeping a `NODE_OPTIONS` from your environment. A
                `node-options` setting in an `.npmrc` is not applied to the
                preview while `bind` is set: npm would replace
                `NODE_OPTIONS` with it and drop the script, so the plugin
                also sets `npm_config_node_options`, which takes precedence
                over every `.npmrc`. The script
                stops the server with an error if it ends up listening on any
                other address. Verified on macOS with Node 25 and
                `@scalar/cli` 2.11.0; not verified on Windows.

                                                  *scalar-preview-cli_version*
    cli_version (string, default: `"latest"`)
                The `@scalar/cli` version or dist-tag to run, e.g. `"2.8.0"`
                to pin it instead of tracking whatever `"latest"` resolves
                to on every run. Must look like a bare version/dist-tag
                (letters, digits, `.`, `+`, `-`); a value containing `:` or
                `/` (e.g. an `npm:`, `github:`, or `file:` package-arg, or a
                URL) is rejected, since `@scalar/cli@<that>` would then be
                resolved as something other than a version of `@scalar/cli`
                itself.

                                                       *scalar-preview-config*
    config      (string or nil, default: `nil`)
                Path to a JSON file with API Reference configuration
                (theme, layout, ...; see `@scalar/cli`'s own docs for its
                shape), passed to the CLI as `-c`/`--config`. A relative
                path is resolved once, to an absolute path, before use.

    Example: >lua
        require("scalar-preview").setup({
          port = 8080,
          cli_version = "2.8.0",
        })
<

6. Known limitations                        *scalar-preview-known-limitations*

- Only preview specs you trust. `@scalar/cli` resolves every `$ref` in the
  document -- including ones pointing outside its directory on the local
  filesystem, and ones pointing at an `http(s)://` URL -- and embeds what
  it finds into the page it serves.
- By default the underlying server listens on all network interfaces, both
  IPv4 and IPv6, not just `localhost`, so anyone on your network can view
  the preview. The CLI has no flag to restrict this; set
  |scalar-preview-bind| (e.g. `"127.0.0.1"`) to limit it to this machine.
  It is off by default so that setups which open the preview from another
  device keep working.
- With the default `cli_version = "latest"`, the exact `@scalar/cli`
  version that runs isn't pinned and can change between runs.
- `npx` runs in the previewed file's directory and looks for an already
  installed `@scalar/cli` in the nearest `node_modules` at or above it (the
  closest directory with a `package.json` or `node_modules`); the search
  stops there and doesn't look further up. If that copy's own
  `package.json` claims a matching version -- the exact
  |scalar-preview-cli_version|, or a range such as `7.x` -- `npx` runs it
  instead of downloading from the registry, so pinning does not rule this
  out. For `latest`, the same happens when the copy's `package.json` has a
  `resolved` equal to `latest`'s current tarball URL. A `.npmrc` in that
  same directory can also point `npx` at a different registry. Don't
  preview specs inside a checkout you don't trust.
- On Windows, a previewed file or a configured |scalar-preview-config|
  path containing a `cmd.exe` metacharacter (` & | ^ % ( ) ! < > " `) is
  refused outright, since `npx` runs through `cmd.exe` there regardless of
  how this plugin invokes it.

See the README for the full, up-to-date list and the reasoning behind each
one: https://github.com/Alnoir-0011/scalar-preview.nvim#known-limitations
